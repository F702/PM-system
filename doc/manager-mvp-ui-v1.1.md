# 管理者项目经营系统 V1.2 — UI/UX 最终设计文档

> 版本：V1.1  
> 日期：2026-08-19  
> 终端：桌面 + 平板 + 手机完整响应式 Web  
> 用户：公司管理者  
> 设计参考：Awwwards 中 Business & Corporate、Data Visualization、Responsive、Clean、Typography、Microinteractions 等获奖/高质量案例的视觉语言。  
> 设计原则：**吸收高级网页的排版、节奏、交互和视觉质感，但不照搬营销网站的炫技。**

---

## 0. 设计方向：Editorial Control Room

最终视觉不是典型“蓝色后台管理系统”，而是：

> **高级编辑排版 + 管理驾驶舱 + 克制微交互。**

参考 Awwwards 获奖站常见特征：

- 大尺度标题和数字；
- 极强的黑白/中性色对比；
- 少量高识别度强调色；
- 大留白与严格网格；
- 清晰的响应式桌面/移动呈现；
- 有意设计的 hover、滚动和状态转换；
- 数据可视化服务于内容，不让图表喧宾夺主；
- 表单也有品牌感，而不是浏览器默认后台风格。

本系统明确**不采用**：

- 3D/WebGL；
- 大面积视频；
- 复杂视差；
- 光标跟随；
- 音效；
- 5 秒页面转场；
- 影响数据阅读的滚动叙事。

---

## 1. 最终视觉系统

### 1.1 色彩

主视觉使用“暖纸白 + 墨黑 + 酸性青柠”形成现代、克制、有辨识度的风格。

```text
Canvas        #F3F1EB  暖灰纸色，全站底色
Surface       #FFFFFF  表单/卡片
Ink           #111111  主文字
Ink-2         #2B2B29  次主文字
Muted         #73736D  辅助文字
Line          #D9D6CF  细边框
Accent        #C8F43D  主操作/当前状态
Accent-ink    #111111
Danger        #D52B1E
Warning       #C96B12
Success       #16734A
Info          #315BFF
```

强调色只用于：

- 主按钮；
- 当前导航；
- 关键选中状态；
- 少量数据强调。

风险使用语义色，不用 Accent 代替风险色。

### 1.2 字体

```css
font-family:
  Inter,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "PingFang SC",
  "Hiragino Sans GB",
  "Microsoft YaHei",
  sans-serif;
```

不依赖第三方在线字体 CDN。

数字：

```css
font-variant-numeric: tabular-nums;
```

### 1.3 字号

桌面：

```text
Display KPI      48–64 / 0.95
Page title       36–44 / 1.05
Section title    22–26
Body             15–16
Table             14
Meta              12–13
```

手机：

```text
Display KPI      36–44
Page title       30–34
Section title    20–22
Body             15–16
Meta              12–13
```

### 1.4 圆角和边框

```text
大容器        24px
卡片          18px
输入框        14px
按钮          999px 胶囊 / 14px 方圆角两类
边框          1px #D9D6CF
```

不使用厚重阴影。

卡片靠：

- 背景色；
- 1px 边框；
- 空间；

形成层次。

### 1.5 动效

```text
hover         120ms
drawer/sheet  180–220ms
page content  200–280ms
```

使用：

```text
opacity
translateY 4–12px
scale 0.985 -> 1
border/background transition
```

禁止 bounce 和夸张弹簧。

## 2. 全局布局

### 2.1 桌面：顶部悬浮导航，不用传统左侧后台栏

最终样式：

```text
┌───────────────────────────────────────────────────────────────────────────┐
│   PM.    驾驶舱   项目   经营   设置       ⌘K 搜索        + 新建    admin ○ │
└───────────────────────────────────────────────────────────────────────────┘

        页面内容从顶部 104px 开始
```

导航条：

```text
position: sticky
height: 64px
margin: 16px 20px
border-radius: 20px
background: rgba(255,255,255,.92)
border: 1px solid Line
backdrop-filter: blur(12px) 仅作为增强，关闭也可用
```

当前导航不是传统蓝底，而是 Accent 胶囊：

```text
[ 驾驶舱 ]
background #C8F43D
color #111
```

### 2.2 手机

顶部：

```text
┌────────────────────────────┐
│ PM.             🔍      ○  │
└────────────────────────────┘
```

底部固定导航：

```text
┌────────────────────────────┐
│ 驾驶舱   项目   经营   设置 │
└────────────────────────────┘
```

- 高度 64px + safe-area；
- 当前项用小型 Accent 胶囊背景；
- 内容底部 padding 至少 96px，绝不被导航遮挡。

## 3. 共用交互组件最终样式

### 3.1 主按钮

```text

```

样式：

```text
height 44–48
padding 0 20
background Accent
color Ink
font-weight 600
border-radius 999px
```

hover：亮度轻微变化 + `translateY(-1px)`。

### 3.2 次按钮

白底、1px 黑灰边框。

### 3.3 风险标签

不是小圆点，而是带文字的圆角标签：

```text

[ 应收逾期 ]
[ 3 天后开标 ]
```

颜色使用淡背景 + 深语义文字。

### 3.4 输入框

```text
height 48
background #FFF
border 1px Line
border-radius 14
```

focus：

```text
border #111
outline 3px rgba(200,244,61,.45)
```

### 3.5 抽屉 / Bottom Sheet

桌面：右侧 480–560px。  
手机：从底部覆盖到约 92vh，顶部有拖动视觉标记，但不依赖手势才能关闭。

│                                               [ 登录 → ]                  │

左侧：

- `#111` 黑底；
- 暖白文字；
- Accent 只用于一个小圆或下划线；
- 大字号 64–84px；
- 数据数字作为静态品牌元素，不展示真实未登录数据。

### 手机

- 去掉分屏；
- 顶部黑色 Hero 高约 34vh；
- `PM.` + “公司项目，一眼看清。”；
- 下半部分登录表单；
- 输入框 52px 高；
- 登录按钮全宽；
- 浏览器键盘弹出后按钮仍可滚动到。

### 状态

错误信息直接显示在密码框下：

```text
账号或密码不正确，请重新输入。
```

不弹浏览器 alert。

## 26. Awwwards 参考原则如何落地

从 Awwwards 的获奖/高质量案例中，**借设计方法，不借营销炫技**：

| 参考特征 | 本系统落地 |
|---|---|
| Clean / Typography | 大号标题、KPI 数字、严格字重和留白 |
| Responsive Design | 同模板 mobile-first，桌面表格转手机卡片 |
| Microinteractions | 行 hover、按钮位移、抽屉过渡、保存反馈 |
| Data Visualization | 用层级、数字、状态代替无意义复杂图表 |
| Unusual Navigation | 放弃传统深色左侧后台栏，改为轻量顶部导航 + 手机底栏 |
| Forms & Input | 大尺寸输入、聚焦状态、金额视觉强化 |
| Content Architecture | 页面围绕管理问题而不是技术模块组织 |

Awwwards 案例常把 Responsive Design、Transitions、Typography、Data Visualization、Microinteractions 作为设计评价/标签维度；本系统只选择能提升可用性和品牌质感的部分。

## 27. UI 对抗性审查

### 是否需要炫酷首页动画？

否。管理者打开系统是为了看异常，动画会延迟信息出现。

### 是否需要复杂图表？

V1 否。四个准确数字 + 风险列表比多个饼图更直接。

### 是否需要侧边栏？

否。只有 4 个一级入口，侧边栏会制造后台模板感和额外空间占用。

### 是否需要手机独立页面？

否。同模板响应式，减少维护分叉。

### 是否需要暗色模式？

V1 否。会使每个状态颜色、表格和组件多一套 QA 成本。

### 是否需要玻璃拟态？

只允许顶部导航轻微 backdrop blur 作为渐进增强，不作为核心视觉依赖。

### 是否需要每个模块一张卡？

否。页面优先用网格、分隔线和留白，减少“卡片套卡片”的传统 SaaS 感。
