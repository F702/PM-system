# 管理者项目经营系统 V1 — MVP 产品文档

> 版本：V1.1  
> 日期：2026-08-19  
> 产品对象：公司管理者（首版仅管理者登录）  
> 核心目标：用最少操作长期保存公司的全部项目事实，并让管理者快速看清项目、风险、成果和经营情况。

---

## 0. 一句话产品定义

这不是员工任务系统，也不是 OA/ERP。

**V1 是一个面向管理者的“公司项目事实库 + 管理驾驶舱”：把进行中和已完成的项目统一保存，在一个地方看全局、找历史、识别异常、核对经营。**

普通员工在 V1 只是“人员数据”，不是系统用户；未来员工端可以复用同一套项目数据，但不影响 V1 的信息架构。

---

## 1. 第一性原理约束

所有 V1 设计必须同时服从以下约束：

1. **首版只有管理者使用**
   - 预期 1–2 个登录账号。
   - 不为普通员工设计工作台、任务流、移动现场操作或通知逻辑。
   - 员工仅作为项目负责人/参与人被记录。

2. **长期数据比短期流程更重要**
   - 系统必须保存进行中、已完成、取消的项目。
   - “已完成项目”不是搬到另一个档案系统，而是仍属于同一项目库。
   - 核心业务数据默认不物理删除。

3. **管理者不是录入员**
   - 每个字段都必须证明它能支持管理判断、历史检索、经营核对或数据追溯。
   - 不能要求管理者复制员工执行层的大量过程记录。
   - 当前项目的“快速更新”目标是 30 秒内完成。

4. **异常优先于展示**
   - 驾驶舱首先告诉管理者“哪里需要关注”，而不是堆很多图表。
   - 风险必须可解释，V1 不使用 AI 猜测风险。

5. **同一事实只保存一处**
   - 项目、客户、合同、发票、回款、文件均有明确唯一事实源。
   - 不建立“项目档案库”和“在办项目库”两套重复数据。

6. **先减少复杂度，再增加自动化**
   - 不因为 AI 辅助开发很快，就接受更多产品功能。
   - AI Coding 缩短编码时间，但不会消除业务状态、数据异常、迁移和维护成本。

## 2. V1 的四个核心管理任务

管理者登录系统后，只需要完成四类任务：

### 2.1 看全局

回答：

- 现在有多少在办项目？
- 哪些项目需要关注？
- 哪些项目马上到关键节点？
- 当前合同额、已开票、已回款、应收是多少？

### 2.2 找项目

回答：

- XX 客户以前做过哪些项目？
- 2023 年做过哪些招标代理项目？
- 某项目负责人是谁？
- 某个已完成项目最终成果和合同在哪里？

### 2.3 判断风险

回答：

- 哪个关键节点已经延期？
- 哪个在办项目很久没有被管理复核？
- 哪笔应收已经超期？
- 哪个监理问题还没有关闭？

### 2.4 核对经营

回答：

- 每个项目的服务合同额是多少？
- 已开票多少？
- 已回款多少？
- 应收多少？
- 哪些项目有逾期回款？

如果一个功能不能明显帮助完成上述四项任务，也不能明显保护长期数据，它默认不进入 V1。

---

## 3. 对抗性审查方法

每个候选功能必须接受以下六个问题：

1. **删除它以后，管理者还能完成四个核心任务吗？**
2. **它是否要求普通员工参与，才能产生价值？**
3. **它是否引入新的状态机、后台任务、权限体系或第三方依赖？**
4. **它的数据能否从已有数据实时推导，而不需要单独保存？**
5. **它至少会每周使用，或者属于“低频但不可逆的数据保护能力”吗？**
6. **它是否可以在未来添加，而不会破坏 V1 数据模型？**

判定规则：

- **保留**：删除后会破坏核心管理任务或长期数据可信度。
- **简化后保留**：有价值，但原方案实现方式过重。
- **移出 V1**：现在不做不会破坏核心闭环，且以后可增量添加。

## 4. 功能对抗性审查结论

| 候选功能 | 攻击问题 | V1 结论 | V1 实现方式 |
|---|---|---|---|
| 管理驾驶舱 | 不做就无法快速看全局 | **保留** | KPI + 风险列表 + 最近关键节点 |
| 全部项目库 | 不做就无法长期保存历史 | **保留** | 在办/已完成/全部共用一张项目表 |
| 全局搜索 | 历史项目多后不做会难找 | **保留** | 搜项目名、编号、客户、文件标题 |
| 客户 | 项目历史检索需要 | **保留** | 轻量客户主数据 |
| 员工/负责人 | 管理项目需要知道责任人 | **保留** | 仅人员数据，不创建员工账号 |
| 服务类型 | 同一项目可有多项服务 | **保留** | 招标/造价/监理/其他作为项目服务 |
| 完整招标工作流 | 管理者并不执行全过程 | **移出 V1** | 只记录阶段、关键日期、结果 |
| 预算明细行 | 管理者 V1 不需要逐行算量 | **移出 V1** | 只保留成果版本和总金额 |
| 造价成果版本 | 版本变化本身是管理事实 | **保留** | 版本号、状态、总额、日期、文件 |
| 监理日志 | 没有员工端时录入成本过高 | **移出 V1** | 只保留管理级问题/整改项 |
| 监理问题 | 逾期问题是管理风险 | **保留** | 标题、责任方、截止、状态 |
| 里程碑 | 风险判断的基础 | **保留** | 关键节点，不做复杂工作流 |
| 风险中心独立模块 | 风险可从已有数据计算 | **不单独建模块** | 驾驶舱风险卡 + 项目过滤视图 |
| 自定义风险规则 | 首版没有规则配置需求 | **移出 V1** | 规则写在代码中，数量少且可解释 |
| 合同 | 管理经营必须 | **保留** | 可多合同，按项目汇总 |
| 发票 | 管理经营必须 | **保留** | 记录实际开票 |
| 回款 | 管理经营必须 | **保留** | 记录实际回款 |
| 发票-回款多对多核销 | 管理层首版不需要会计级核销 | **移出 V1** | 回款直接关联合同 |
| 完整财务会计 | 产品目标不是会计软件 | **移出 V1** | 只做合同/开票/回款/应收 |
| 项目文件 | 长期档案必需 | **保留** | 私有对象存储，文件元数据入库 |
| 复杂文件版本系统 | 对管理者过重 | **简化后保留** | 文件不可覆盖；可填“版本标签/最终版” |
| 通用 Excel 映射器 | 维护成本很高 | **移出 V1** | 只支持固定模板 |
| 历史项目导入 | 没有它历史迁移成本太高 | **保留** | 一个固定“历史项目模板” |
| 通用报表中心 | 驾驶舱/列表已能回答大部分问题 | **移出 V1** | 当前页面筛选 + Excel 导出 + 浏览器打印 |
| 企业微信通知 | 管理者主动打开系统即可 | **移出 V1** | 真实产生“忘看系统”问题后再加 |
| 员工登录/RBAC | V1 没有员工用户 | **移出 V1** | 仅管理者账号 |
| 小程序/PWA/离线 | 管理者 PC 使用不是现场作业 | **移出 V1** | 响应式 Web |
| AI 文档解析 | 有价值但引入供应商/审核/异步复杂度 | **移出 V1** | V1.1 再按真实录入负担决定 |
| RAG/文档聊天 | 不影响核心闭环 | **移出 V1** | 后续需求验证 |
| AI 风险判断 | 不可解释且没必要 | **禁止进入 V1** | 使用确定性规则 |
| 审计日志 | 长期数据必须能追溯 | **简化后保留** | 只审计核心数据变更 |
| 物理删除 | 会破坏历史可信度 | **禁止** | 作废/取消/隐藏，保留原记录 |
| 数据备份/恢复 | 数据不可逆保护 | **保留** | 自动备份 + 定期恢复演练 |

## 5. V1 信息架构

一级导航只保留四项：

```text
驾驶舱
项目
经营
设置
```

顶部固定存在：

```text
全局搜索
当前账号
```

### 为什么没有“风险”一级菜单

风险不是一种新的业务数据，而是从项目节点、回款期限、监理问题等现有事实计算出来的“视图”。

点击驾驶舱的某个风险卡后，进入已经带过滤条件的项目/经营列表即可。

### 为什么没有“历史档案”一级菜单

历史项目和在办项目必须属于同一个项目库。

项目页提供：

```text
在办 | 已完成 | 全部
```

避免形成两个事实源。

---

## 6. 项目生命周期

V1 项目只允许以下生命周期状态：

```text
在办
已完成
已取消
```

不增加“归档中”“封存”“关闭”“已结项”等相近状态。

### 6.1 在办

- 参与驾驶舱在办项目统计。
- 参与临期、延期、长期未复核等风险计算。
- 可以更新服务阶段和关键节点。

### 6.2 已完成

- 仍可全局搜索。
- 仍可查看合同、回款、成果、文件和历史记录。
- 不参与一般进度风险。
- 如果仍有应收，可以继续出现在经营风险中。

### 6.3 已取消

- 保留取消原因和取消日期。
- 不物理删除。
- 仍可搜索和查看。

## 7. 项目数据最小集

### 7.1 项目主数据

必填：

- 项目名称
- 客户
- 至少一个服务类型
- 负责人
- 项目状态

自动：

- 系统 ID
- 业务年份（新建时默认当前年份，可在更多信息中调整）
- 创建时间
- 修改时间
- 最后管理复核时间

选填：

- 公司内部项目编号
- 委托/开始日期
- 计划完成日期
- 实际完成日期
- 项目/采购标的金额
- 备注

### 7.2 金额口径必须分开

系统不得使用一个模糊的“项目金额”。

至少区分：

- 项目/采购标的金额
- 造价成果金额
- 服务合同金额
- 已开票金额
- 已回款金额
- 应收金额

其中：

```text
应收 = 有效服务合同金额合计 - 已回款金额合计
```

V1 的“经营”不是会计收入确认。

## 8. 项目服务

一个项目可以有一个或多个服务：

```text
招标代理
造价/预结算
监理
其他
```

每个服务只记录管理层真正需要的字段：

- 服务类型
- 当前阶段
- 负责人
- 计划完成日期
- 实际完成日期
- 备注

“其他”用于记录不属于招标、造价或监理的非常规项目服务。选择“其他”时，必须补充一条简短的服务说明，以便后续检索和经营汇总时知道该项目实际提供的服务；它不新增任何专属流程、阶段字典或业务表。

阶段值使用固定字典，不做流程引擎。

## 9. 三类业务的 V1 管理数据

### 9.1 招标代理

保留：

- 当前阶段
- 公告日期（可空）
- 投标截止时间（可空）
- 开标时间（可空）
- 中标/成交金额（可空）
- 中标单位（可空）
- 结果日期（可空）
- 关键文件

不保留：

- 完整 checklist
- 答疑/补遗执行流程
- 评标任务分工
- 员工操作步骤

### 9.2 造价/预结算

保留成果版本：

- 成果类型
- 版本标签（V1/V2/终稿等）
- 状态（草稿/复核/最终）
- 总金额
- 日期
- 关联文件
- 备注

不保留：

- 工程量明细行
- 单价库
- 自动差异行比较
- AI 预算建议

系统可自动展示：

```text
首个版本金额
最新版本金额
金额变化
变化比例
```

### 9.3 监理

只保留管理级问题：

- 问题标题
- 严重程度（一般/重要）
- 责任方
- 发现日期
- 整改期限
- 状态（待处理/处理中/已关闭）
- 关闭日期
- 说明
- 关联文件/照片

不做完整监理日志。

---

## 10. 里程碑

每个项目服务可有多个关键节点。

字段：

- 节点名称
- 计划时间
- 实际完成时间
- 是否关键节点
- 备注

状态不单独手填，尽量由日期推导：

```text
实际完成时间存在 -> 已完成
实际完成时间为空且计划时间 < 当前时间 -> 已延期
实际完成时间为空且计划时间 >= 当前时间 -> 待完成
```

减少“日期显示过期，但状态还写正常”的矛盾。

## 11. 风险规则

风险不使用 AI，V1 只做确定性规则。

### R1 关键节点延期

```text
在办项目
AND 关键节点实际完成时间为空
AND 计划时间 < 今天
=> 红色：关键节点延期
```

### R2 七日内关键节点

```text
在办项目
AND 关键节点未完成
AND 0 <= 计划时间 - 今天 <= 7天
=> 橙色：7日内到期
```

### R3 长期未管理复核

```text
在办项目
AND 今天 - last_reviewed_at >= 14天
=> 橙色：14日未复核
```

管理者在项目页点击“确认当前状态”即可刷新 `last_reviewed_at`，不要求修改字段。

### R4 逾期应收

合同可选填写计划回款日期。

```text
合同仍有应收
AND 计划回款日期 < 今天
=> 红色：逾期应收
```

### R5 监理整改逾期

```text
问题未关闭
AND 整改期限 < 今天
=> 红色：整改逾期
```

### 风险排序

默认：

1. 红色风险
2. 逾期天数更多
3. 最近 7 日到期
4. 其他提醒

V1 不实现“风险分数 82/100”之类难解释的评分。

## 12. 管理驾驶舱

首屏目标：

> **30 秒知道公司哪里需要关注。**

### 12.1 第一行 KPI

只保留四个：

- 在办项目
- 需要关注项目
- 当前应收
- 本月已回款

每个 KPI 可点击进入过滤后的列表。

### 12.2 需要关注

显示最多 8 条：

- 项目
- 风险原因
- 逾期/剩余天数
- 负责人
- 快速进入项目

### 12.3 近期关键节点

显示未来 14 天关键节点。

### 12.4 项目概览

显示：

- 项目
- 服务类型
- 当前阶段
- 负责人
- 下一节点
- 风险标记

### 12.5 不进入 V1 的驾驶舱元素

- 地图
- 饼图矩阵
- AI 总结
- 复杂趋势图
- 可拖拽卡片
- 自定义仪表盘
- 个人待办

## 13. 项目列表与历史检索

项目列表默认提供三个 Tab：

```text
在办 | 已完成 | 全部
```

筛选：

- 年份
- 客户
- 服务类型
- 负责人
- 状态
- 是否有风险

搜索：

- 项目名称
- 项目编号
- 客户名称

列表列：

- 项目名称
- 客户
- 服务类型
- 负责人
- 状态
- 当前/最终阶段
- 下一关键节点
- 风险
- 最后复核时间

### 历史项目原则

- 已完成项目永不自动删除。
- 年份增加不会创建新数据库或新表。
- 所有年份使用同一数据结构。
- “历史”只是过滤条件，不是另一套产品。

仅管理者可见最近核心数据变更。

## 15. “快速更新”是 V1 的关键操作

由于没有员工端，管理者必须能很轻地维护当前状态。

项目页点击 `快速更新` 后，只显示：

- 项目状态
- 各服务当前阶段
- 下一关键节点和日期
- 需要关闭/延期的节点
- 一段管理备注

保存后自动：

- 更新 `last_reviewed_at`
- 重算风险
- 记录审计事件

目标：常规项目状态更新 **30 秒内完成**。

## 16. 经营模块

经营页是跨项目的管理视图。

### 16.1 顶部

- 服务合同总额
- 已开票
- 已回款
- 应收
- 逾期应收

默认展示全公司范围；选择经营范围或点击某个聚合行后，全部金额与项目数必须同步切换为该范围内项目的统计结果。

### 16.2 合同

字段：

- 项目
- 合同编号
- 合同金额
- 签订日期
- 计划回款日期（可空）
- 备注
- 合同文件

一个项目允许多个合同/补充协议。

### 16.3 发票

字段：

- 合同
- 发票编号
- 开票日期
- 金额
- 附件（可空）
- 备注

### 16.4 回款

字段：

- 合同
- 回款日期
- 金额
- 备注/银行摘要

V1 不做发票与回款的逐笔核销。

### 16.5 经营过滤

- 年份
- 客户
- 服务类型（招标代理/造价/预结算/监理/其他）
- 项目
- 是否逾期
- 是否已完成项目

“项目已完成”不能隐藏仍有应收的项目。

### 16.6 属性聚合与项目下钻

经营页必须支持以 **年份、服务类型、客户** 中任一属性查看经营。管理者可以：

1. 选择经营范围（任意组合年份、服务类型、客户等过滤条件）；
2. 选择聚合维度：`按年份`、`按服务类型` 或 `按客户`；
3. 查看每个属性值下的全部项目、项目数，以及合同额、已开票、已回款、应收四项总额；
4. 点击某个属性值，进入已带对应筛选条件的项目经营列表。

聚合行的金额口径如下：

```text
合同额 = 范围内项目的有效服务合同金额合计
已开票 = 范围内项目的有效发票金额合计
已回款 = 范围内项目的有效回款金额合计
应收   = 合同额 - 已回款
```

一个项目拥有多个服务类型时，在“按服务类型”视图中会分别出现在各个服务类型下；每个服务类型行内按项目去重统计。因此各服务类型行相加不必等于全公司总额，界面必须明确说明这一点，避免把重叠服务当作可相加的财务分项。

## 17. 文件与长期档案

### 17.1 文件原则

- 文件二进制保存在对象存储。
- 数据库只保存文件元数据和项目关系。
- 上传后不原地覆盖。
- 新版本作为新文件记录保存。
- 核心文件不通过 UI 物理删除。

### 17.2 文件字段

- 所属项目
- 分类
- 标题
- 版本标签（可空）
- 是否最终版
- 文件名
- MIME 类型
- 文件大小
- 对象存储 key
- checksum
- 上传时间
- 备注

### 17.3 文件分类 V1 固定

- 合同
- 招标
- 造价成果
- 监理
- 发票
- 项目成果
- 其他

不做无限自定义文件夹树。

## 18. 历史项目迁移

第一版长期价值取决于能否把历史项目快速建立索引。

### 18.1 不追求一次性结构化所有历史资料

历史迁移分三层：

#### A. 所有历史项目：最小索引

至少：

- 项目名称
- 客户
- 年份
- 服务类型
- 负责人（若已知）
- 状态
- 完成日期（若已知）
- 备注

#### B. 近 12–24 个月 / 仍有经营价值的项目

补充：

- 合同
- 回款
- 造价最终金额
- 关键成果

#### C. 更老项目

- 保留项目索引。
- 上传原 Excel/PDF/最终成果文件。
- 不强制人工重录所有旧过程数据。

### 18.2 固定历史项目模板

V1 只支持一个固定 Excel 模板。

推荐字段：

```text
项目编号
项目名称*
客户*
年份*
服务类型*
负责人
状态*
开始日期
计划完成日期
实际完成日期
项目/采购标的金额
服务合同额（汇总，可空）
造价最终成果金额（可空）
备注
```

### 18.3 导入流程

```text
上传固定模板
→ 预检
→ 展示错误行
→ 展示“新增/重复/忽略”统计
→ 管理者确认
→ 写入数据库
→ 保存原始导入文件和批次记录
```

不提供字段拖拽映射器。

## 24. 核心用户流程

### 流程 A：每天打开系统

```text
登录
→ 驾驶舱

→ 点击风险项目
→ 查看原因
→ 快速更新/修改日期/查看经营
```

### 流程 B：找一个过去项目

```text
顶部搜索“学校改造”
→ 项目结果
→ 打开已完成项目
→ 查看最终成果、合同、文件、负责人
```

```text

→ 打开项目
→ 快速更新
→ 确认当前阶段/下一节点
→ 保存
→ 风险自动重算
```

### 流程 D：核对应收

```text
经营
→ 逾期应收
→ 查看项目/合同
→ 新增回款
→ 应收自动重新计算
```

```text
下载固定模板
→ 整理最小项目索引
→ 上传
→ 修正错误行
→ 确认导入
→ 批量补充关键文件
```

## 25. MVP 验收标准

### 25.1 易用性

- 管理者首次登录不看说明，也能找到“项目”“经营”和搜索。
- 新建项目必填字段不超过 5 个逻辑项。
- 常规项目状态更新可在 30 秒左右完成。
- 找一个已完成项目不超过：搜索 → 点击，两步。
- 任何风险都能点开看到明确原因，不出现不可解释“风险分”。

### 25.2 数据完整性

- 在办、已完成、已取消项目均可长期保存和搜索。
- 核心数据没有普通用户“永久删除”按钮。
- 金额口径不会混用。
- 文件不会被新上传版本覆盖。
- 导入失败不会产生“写了一半”的项目。

### 25.3 管理价值

管理者能够直接回答：

- 当前有多少在办项目？
- 哪些项目已经延期？
- 未来 7 天有哪些关键节点？
- 哪些项目 14 天没有管理复核？
- 公司当前合同额/已开票/已回款/应收分别是多少？
- 某个年份、服务类型或客户下有哪些项目，合同额/已开票/已回款/应收合计分别是多少？
- 哪些应收已经逾期？
- 某客户过去有哪些项目？
- 某历史项目最终成果文件在哪里？

### 25.4 可维护性

- V1 无员工端。
- V1 无消息队列。
- V1 无独立搜索服务。
- V1 无工作流引擎。
- V1 无 AI 运行依赖。
- V1 无通用低代码配置。
- V1 无“必须靠后台定时任务才正确”的业务数据；风险可实时计算。

## 27. V1.1 以后只依据真实使用问题扩展

不是按“功能路线图”自动增加功能，而是按真实摩擦扩展。

典型触发条件：

- 管理者每周大量重复抄合同字段 → 评估 AI 文档提取。
- 管理者经常忘记打开驾驶舱 → 评估企业微信提醒。
- 员工需要自己更新进度 → 开始员工端。
- 现场监理确实高频移动录入 → 再做小程序。
- 项目数量使普通搜索明显变慢/不好用 → 再评估全文索引。
- 财务逐笔核销成为真实需求 → 增加发票-回款核销。

**没有真实问题，不增加系统复杂度。**
